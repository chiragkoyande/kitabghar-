Experiment No. 6
Title: Develop a Node.js Application using Express.js and Mongoose to Connect with MongoDB
Aim:

To build a modular backend web server using Node.js, the Express.js framework, and Mongoose ODM, establishing a persistent database connection with MongoDB and exposing structured RESTful endpoints.

Tools Used:
  • Node.js runtime v22 (ES Modules)
  • Express.js v4.21.1 web framework
  • Mongoose v8.7.1 ODM
  • MongoDB Atlas cloud database
  • Helmet, CORS, Morgan, Express JSON body parsing middleware
  • JSON Web Token (jsonwebtoken) & bcryptjs for security
Methodology:
Express App Initialization → Middleware Pipeline Mounting → Mongoose DB Connection → Schema & Model Compilation → Controller Business Logic → Route Mounting → Client Integration

The backend server is structured following MVC design patterns. Express initializes HTTP server listeners and mounts a robust middleware chain (Helmet security headers, CORS, body parsers, logging). Mongoose connects to the MongoDB cluster via connection pooling. Schemas define document shapes, types, and validation constraints. Controllers encapsulate business logic and database queries, which routes map to HTTP verbs.

Theory:

Express.js is a minimalist, flexible Node.js web application framework that provides a robust set of features for web and mobile applications. It simplifies server creation through a modular middleware pipeline where incoming HTTP requests pass through sequential functions capable of inspecting, modifying, or terminating requests.

Mongoose is an Object Data Modeling (ODM) library for MongoDB and Node.js. It manages relationships between data, provides schema validation, translates between JavaScript objects and BSON representations, and exposes rich query builders. Mongoose schemas define the fields, data types, default values, validators, and indexing strategies for collections.

In a 3-tier web architecture, Express functions as the Application/Logic Tier mediating between the Presentation Tier (React client) and the Data Tier (MongoDB). Security middleware like Helmet sets HTTP response headers, CORS manages cross-origin resource sharing, and JWT authentication middleware guards sensitive business endpoints.

Code Block 6.1: Express Server Setup & Middleware Pipeline

File: server/server.js (Lines 1–32) — Initializes Express, configures security middleware, connects database, and mounts routes.

import express from "express";
import dotenv from "dotenv";
import cors from "cors";
import helmet from "helmet";
import morgan from "morgan";
import connectDB from "./config/db.js";
import bookRoutes from "./routes/bookRoutes.js";
import authRoutes from "./routes/authRoutes.js";

dotenv.config();
connectDB();

const app = express();

app.use(helmet());
app.use(cors({ origin: process.env.CLIENT_ORIGIN || "http://localhost:5173" }));
app.use(express.json());
app.use(morgan("dev"));

app.get("/api/health", (req, res) => {
  res.json({ status: "ok", service: "kitabghar-api", database: "mongodb" });
});

app.use("/api/books", bookRoutes);
app.use("/api/auth", authRoutes);

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`Server running on port ${PORT}`));

Code Block 6.2: Mongoose Schema Definition: Book Model

File: server/models/Book.js (Lines 1–24) — Defines schema fields, data types, validation rules, and indexes for books collection.

import mongoose from "mongoose";

const bookSchema = new mongoose.Schema(
  {
    title: { type: String, required: true, trim: true },
    author: { type: String, required: true, trim: true },
    description: { type: String, required: true },
    category: { type: String, required: true },
    coverImage: { type: String, default: "" },
    totalCopies: { type: Number, required: true, min: 1, default: 1 },
    availableCopies: { type: Number, required: true, min: 0, default: 1 },
    language: { type: String, default: "English" },
    status: { type: String, enum: ["active", "archived"], default: "active" }
  },
  { timestamps: true }
);

bookSchema.index({ title: "text", author: "text", category: "text" });

export const Book = mongoose.model("Book", bookSchema);

Result:

A complete backend web application was built using Node.js, Express.js, and Mongoose connected to MongoDB. The server establishes persistent database connectivity, validates document schemas, and exposes robust public and protected RESTful API endpoints.

The API returned live JSON data for public resources, while authentication issued a token and protected requests used that session to return reader-specific data. Schema, controller, and middleware responsibilities were visible across the observed requests.

Conclusion:

The experiment confirmed that Express.js and Mongoose form an efficient, expressive backend foundation for Node.js web development. The middleware architecture provides clear separation between security, routing, and business logic.

Mongoose models provide strong data validation and schema integrity while retaining the schema flexibility of MongoDB, ensuring a secure and scalable backend service.

This backend architecture demonstrates how Express routing, Mongoose models, and JWT middleware combine to deliver a secure, database-backed API.
