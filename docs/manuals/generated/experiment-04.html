Experiment No. 4
Title: Develop a Single Page Application (SPA) using React Router, Hooks, and Component Lifecycle Methods
Aim:

To develop a client-side Single Page Application (SPA) using React Router DOM v6, manage view navigation without full-page HTTP reloads, extract dynamic URL parameters with useParams, and coordinate lifecycle-equivalent side effects using custom Hooks.

Tools Used:
  • React 18.3 & React Router DOM v6.28.0
  • Vite 5 development server
  • HTML5 History API (pushState, replaceState, popstate)
  • Chrome DevTools Network panel for zero-reload verification
Methodology:
BrowserRouter Provider Setup → Declarative Route Tree Definition → NavLink Client Navigation → Dynamic Route Parameter Extraction → Protected Route Guarding → Network Tab Zero-Reload Audit

BrowserRouter wraps the application root to subscribe to browser history changes. Routes and Route declarations define the URL-to-component mappings. Navigation is managed exclusively via NavLink and Link components, which intercept anchor clicks and invoke the HTML5 History API. Dynamic book details are addressed through parameterized routes (/books/:id) and resolved via useParams(). Protected routes redirect unauthorized readers using custom auth guards.

Theory:

Single Page Applications (SPAs) rewrite the traditional multi-page web paradigm. Rather than requesting a fresh HTML document from the server on every navigation action, an SPA loads a single root HTML document once. Subsequent view transitions are performed by client-side JavaScript dynamically rewriting the DOM tree in response to URL changes.

React Router DOM provides declarative client-side routing. BrowserRouter uses the browser's native HTML5 History API (pushState, replaceState, and the popstate event) to keep the UI synchronized with the browser's address bar. The <Routes> and <Route> elements match location pathnames to component trees, supporting nested routes and layout sharing via <Outlet />.

Dynamic routing is achieved using route parameters (e.g., path='books/:id'). The useParams() hook extracts route parameters from the current URL, enabling components to perform parameterized data fetching in useEffect(). Route protection is implemented by wrapping private routes in guard components that inspect authentication tokens and conditionally render either child outlets or <Navigate to='/login' replace />.

Case Study Context:

The client-side routing architecture enables readers to navigate seamlessly between the Homepage (/), Book Catalogue (/books), dynamic Book Details (/books/:id), Membership Tiers (/membership), Authentication (/login, /register), and a Protected Reader Dashboard (/dashboard).

The experiment documents both the main Kitab Ghar application routing switchboard (client/src/App.jsx) and the standalone React Router demonstration suite (experiments/exp4/), confirming zero-reload client-side navigation across both implementations.

Code Block 4.1: Declarative SPA Route Tree & Route Guarding

File: client/src/App.jsx (Lines 1–11) — Defines the route switchboard, nested layout routes, parameter paths, and protected routes.

import React from "react";
import { Navigate, Route, Routes } from "react-router-dom";
import Layout from "./components/Layout";
import ProtectedRoute from "./components/ProtectedRoute";
import { useAuth } from "./context/AuthContext";
import { AdminPage, BookDetailsPage, BooksPage, DashboardPage, HomePage, LoginPage, MembershipPage, RegisterPage } from "./pages/Pages";

function AdminRoute() {
  const { user } = useAuth();
  return user?.role === "admin" ? <AdminPage /> : <Navigate to="/dashboard" replace />;
}

export default function App() {
  return (
    <Routes>
      <Route element={<Layout />}>
        <Route index element={<HomePage />} />
        <Route path="books" element={<BooksPage />} />
        <Route path="books/:id" element={<BookDetailsPage />} />
        <Route path="membership" element={<MembershipPage />} />
        <Route path="login" element={<LoginPage />} />
        <Route path="register" element={<RegisterPage />} />
        <Route element={<ProtectedRoute />}>
          <Route path="dashboard" element={<DashboardPage />} />
          <Route path="admin" element={<AdminRoute />} />
        </Route>
        <Route path="*" element={<HomePage />} />
      </Route>
    </Routes>
  );
}

Code Block 4.2: Dynamic Parameter Extraction with useParams Hook

File: experiments/exp4/src/pages/BookDetailsPage.jsx (Lines 8–28) — Extracts :id from the URL and fetches corresponding book data on mount.

export default function BookDetailsPage() {
  const { id } = useParams();
  const navigate = useNavigate();
  const [book, setBook] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // Lifecycle effect: triggers when 'id' parameter changes
    const foundBook = booksCatalogue.find((b) => b._id === id);
    setBook(foundBook || null);
    setLoading(false);
    document.title = foundBook ? `${foundBook.title} · Kitab Ghar` : "Book Details";
    window.scrollTo(0, 0);
  }, [id]);

  if (loading) return <div className="spinner">Loading book details...</div>;
  if (!book) return <div className="error-box">Book not found in catalogue.</div>;

  return (
    <div className="book-details-view">
      <button onClick={() => navigate(-1)} className="btn-back">← Back to Catalogue</button>
      <h1>{book.title}</h1>
      <p className="author">By {book.author}</p>
      <span className="badge">{book.category}</span>
    </div>
  );
}

Result:

A robust Single Page Application was successfully implemented using React Router DOM v6. Client-side routing, dynamic parameter extraction via useParams, route protection via custom auth guards, and lifecycle effects via useEffect were thoroughly validated with zero full-page reloads.

The route runs confirmed zero-reload view changes, correct extraction of the dynamic book identifier, and redirection of unauthenticated users before protected content was displayed.

Conclusion:

The experiment confirmed that React Router DOM provides powerful, declarative routing capabilities that transform multi-component React applications into cohesive Single Page Applications.

The combination of useParams, useNavigate, and ProtectedRoute guards provides a production-ready routing architecture that delivers desktop-like speed and responsiveness to web users.

This experiment combines React Router paths, hooks, and authentication guards into a maintainable navigation structure for the reader workflow.
