Experiment No. 9
Title: Develop a Full-Stack MERN Application by Integrating React Frontend with Express Backend using Axios / Fetch API
Aim:

To develop and deploy a complete full-stack MERN (MongoDB, Express.js, React 18, Node.js) web application for Kitab Ghar, integrating the client-side user interface with the backend RESTful API via asynchronous HTTP requests (Fetch API / Axios) with end-to-end data flow.

Tools Used:
  • MongoDB Atlas (Data Tier)
  • Express.js & Node.js (Application / API Tier)
  • React 18 & Vite (Presentation / UI Tier)
  • Fetch API / Axios HTTP client with Bearer token interceptor
  • CORS middleware for cross-origin communication
  • Google Chrome DevTools Network tab for HTTP timing inspection
Methodology:
React UI Action → Fetch API Asynchronous Request → Express Route & Controller → Mongoose Query → MongoDB BSON Document Retrieval → JSON HTTP Response → React State Mutation → Virtual DOM Re-render

The integration follows an end-to-end lifecycle. The React client delegates all network communication to a unified helper (client/src/services/api.js). Requests attach JWT tokens from localStorage. The Express server processes requests through Helmet, CORS, and auth middleware, delegates queries to Mongoose models, and returns structured JSON responses that update React state variables.

Theory:

The MERN stack is an all-JavaScript software stack comprising MongoDB, Express.js, React, and Node.js. By utilizing JavaScript across all architectural layers—from database queries (BSON/JSON) to server-side logic and client-side rendering—the MERN stack minimizes context switching and facilitates unified data modeling across the full application lifecycle.

Asynchronous client-server communication in modern web applications relies on the Fetch API or Axios. These libraries issue asynchronous HTTP requests using JavaScript Promises, allowing the user interface to remain responsive while awaiting server responses. Centralized API clients attach authorization headers, handle base URLs, and format error messages uniformly.

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that restricts HTTP requests made by client scripts to a different origin (domain, protocol, or port) than the one serving the client. In a decoupled MERN architecture where the Vite client runs on port 5173 and the Express server runs on port 5000, CORS middleware must be configured to permit cross-origin headers, methods, and credentials.

Code Block 9.1: Unified React API Client Service

File: client/src/services/api.js (Lines 1–22) — Encapsulates Fetch API calls, attaches JWT Bearer tokens, and parses JSON responses.

const API_BASE = import.meta.env.VITE_API_URL || "http://localhost:5000/api";

export async function apiRequest(path, options = {}) {
  const token = localStorage.getItem("kitabghar-token");
  const headers = {
    "Content-Type": "application/json",
    ...(token ? { Authorization: `Bearer ${token}` } : {}),
    ...(options.headers || {})
  };

  const response = await fetch(`${API_BASE}${path}`, {
    ...options,
    headers
  });

  const data = await response.json();
  if (!response.ok) {
    throw new Error(data.message || "An error occurred during the request.");
  }
  return data;
}

Code Block 9.2: React Component Consuming End-to-End API Data

File: client/src/pages/Pages.jsx (Lines 11–16) — Custom hook executing asynchronous API requests and binding results to component state.

function useApiData(path) {
  const [state, setState] = useState({ loading: true, data: null, error: "" });

  useEffect(() => {
    let active = true;
    setState({ loading: true, data: null, error: "" });

    apiRequest(path)
      .then((data) => active && setState({ loading: false, data, error: "" }))
      .catch((err) => active && setState({ loading: false, data: null, error: err.message }));

    return () => { active = false; };
  }, [path]);

  return state;
}

Result:

A complete full-stack MERN application was successfully integrated. The React frontend, Express web server, Node.js runtime, and MongoDB Atlas database communicate seamlessly through asynchronous HTTP requests, providing end-to-end data flow from database to user interface.

The completed workflow showed that React forms and pages exchanged JSON with Express, Mongoose persisted the changes, and the returned state was reflected in the dashboard and catalogue without relying on static client data.

Conclusion:

The experiment confirmed that the MERN stack offers an exceptionally productive and unified architecture for modern web applications. The shared use of JavaScript/JSON eliminates impedance mismatch between layers.

The integration of a centralized API client with token interception and React state hooks provides a robust foundation for building secure, scalable full-stack web platforms.

This experiment validates a practical MERN integration in which client state, protected API requests, and MongoDB persistence operate as one end-to-end rental application.
