Title: Create a React Application using Functional Components, JSX, Props, and State
Aim:

To build a modular React application using functional components, JSX declarative markup, unidirectional prop data flow, and component-level state management with the useState and useEffect hooks, using the Kitab Ghar codebase as the primary case study.

Tools Used:
  • React 18.3 & React DOM

  • CSS3 with modular custom properties
  • Google Chrome Developer Tools for component inspection
Methodology:
Vite Application Setup → Functional Component Decomposition → JSX Hierarchy Composition → Props Interface Passing → useState State Management → useEffect Side Effects Execution

The Kitab Ghar React client was architected through functional decomposition. Component responsibility is strictly delineated: App provides top-level routing, Pages implements view containers, and BookCard serves as a pure presentation component. Props flow unidirectionally from stateful parent containers to stateless children, while user interactions trigger state mutations via useState dispatcher functions.

Theory:

React is a component-driven JavaScript library for building user interfaces. Functional components are JavaScript functions that accept an arbitrary inputs object called 'props' and return a React element described in JSX syntax. Unlike legacy class components, modern React applications rely exclusively on functional components paired with Hooks.

JSX (JavaScript XML) is a syntax extension that enables developers to write HTML-like structures directly inside JavaScript. JSX expressions compile down to React.createElement() calls. JSX supports dynamic embedding via curly braces ({expression}), conditional rendering through logical operators (&&, ? :), and list rendering via Array.prototype.map().

Props (properties) provide a mechanism for unidirectional data flow from parent to child components. Props are immutable from the child's perspective. The useState Hook enables functional components to maintain private, reactive state variables; calling a state updater function schedules a re-render to synchronize the Virtual DOM with the real browser DOM.

Code Block 3.1: Functional Component with Props: BookCard

File: client/src/components/BookCard.jsx (Lines 1–18) — Reusable presentation component receiving a book prop and rendering JSX.

import React from "react";
import { Link } from "react-router-dom";

export default function BookCard({ book }) {
  const tone = book.category?.toLowerCase().includes("mystery") ? "wine"
    : book.category?.toLowerCase().includes("fiction") ? "coffee" : "sage";

  return (
    <article className="book-card">
      <Link to={`/books/${book._id}`}>
        <div className={`book-cover cover-${tone}`}>
          {book.coverImage ? (
            <img className="book-cover-image" src={book.coverImage} alt={`${book.title} cover`} />
          ) : (
            <>
              <span>KITAB GHAR</span>
              <strong>{book.title}</strong>
              <small>{book.category}</small>
            </>
          )}
        </div>
        <div className="book-card-body">
          <p className="book-category">{book.category}</p>
          <h2>{book.title}</h2>
          <p className="book-author">{book.author}</p>
          <span className={`availability ${book.availableCopies > 0 ? "available" : "unavailable"}`}>
            {book.availableCopies > 0 ? `${book.availableCopies} available` : "Currently out"}
          </span>
        </div>
      </Link>
    </article>
  );
}

Code Block 3.2: State Management & List Rendering: BooksPage

File: client/src/pages/Pages.jsx (Lines 17–42) — Manages search, category, and sort state via useState and maps data to BookCard props.

export function BooksPage() {
  const [query, setQuery] = useState("");
  const [category, setCategory] = useState("");
  const [availability, setAvailability] = useState("");
  const [sortMode, setSortMode] = useState("popular");

  const requestParams = new URLSearchParams();
  if (query.trim()) requestParams.set("search", query.trim());
  if (category) requestParams.set("category", category);
  if (availability) requestParams.set("availability", availability);

  const requestPath = requestParams.toString() ? "/books?" + requestParams.toString() : "/books";
  const { loading, data, error } = useApiData(requestPath);
  const books = data?.books || [];

  return (
    <div className="books-page">
      <input
        type="search"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Search by title or author..."
      />
      <div className="book-grid">
        {books.map((book) => (
          <BookCard key={book._id} book={book} />
        ))}
      </div>
    </div>
  );
}

Result:

The Kitab Ghar React application successfully demonstrates functional components, JSX syntax, prop data passing, and state management via Hooks. Reusable components cleanly encapsulate UI logic and render responsive, dynamic views based on reactive state changes.

The visible application confirmed that JSX rendered component output, props carried book and plan data, and useState re-rendered the catalogue whenever the user changed an input or selection.

Conclusion:

The experiment confirmed that React's component-based architecture and functional programming paradigms foster clean separation of concerns, high reusability, and maintainable front-end codebases.

The useState and useEffect Hooks adequately replace class component lifecycle methods, offering a declarative, intuitive approach to state and side-effect coordination.

This experiment provides a clear React foundation in which reusable functional components and state-driven rendering can be extended into larger client-side features.
